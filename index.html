Living PRD (Product Requirements Document)

Updated every week as we test with real users and learn what works.

1. Target User & The Job to Be Done

Who is this for? NYU Stern MBA classmates who read at least one book a month for pleasure, starting with me. I can reach them through class, clubs and group chats.

The painful "Before" workflow: After finishing a book they loved, they look for the next one on Instagram, Goodreads, Amazon or bookstore tables. Every channel pushes the same bestsellers, and star ratings say nothing about why a book worked for them. They give up and pick whatever is trending, or nothing.

The "After" workflow with this product: In about five minutes they fill in a short reflection template (three words for the book, the one moment they still remember, what it changed in them). Hidden Shelf turns that into a taste profile and returns five lesser-known books from a large open catalog, each with a reason.

2. Scope & Explicit Non-Goals

  • In Scope (Core Workflow): Pick a book you loved → write the structured reflection → get five hidden-gem recommendations with a "why you" explanation.
  • Out of Scope #1: Points or rewards for reviews that can be used to borrow or buy books.
  • Out of Scope #2: Social features: book clubs, following other readers, comments.
  • Out of Scope #3: Our own book database and affiliate shopping links. We use the free Open Library catalog instead.

3. How It Works Under the Hood & Riskiest Assumption (PRD v2)

Biggest risk: That a structured reflection actually leads to better recommendations than bestseller lists or star ratings, and that readers will take five minutes to write one. A second, technical risk: Open Library's subject tags are messy (missing tags, children's books, self-help), so the results can feel random.

How Build 2 tests it:

  • The app now runs on real books with live Open Library data instead of a sample shelf, so I can see whether the five results actually feel like hidden gems.
  • PostHog tracks each step (book_searched → reflection_submitted → recommendations_shown), so I can see whether people finish the reflection or drop off, and session replays show where they hesitate.
  • Pod testing: classmates try it on a book they love and tell me if they would read at least one of the five.

How the app works:

  1. Frontend (browser): one HTML page (prototype/index.html) served on localhost. No backend yet.
  2. API call 1: the book title goes to the Open Library Search API, which returns matching books and their subjects.
  3. Matching: the user's three words are mapped to subjects (e.g. quiet → Solitude) and combined with the book's own subjects.
  4. API calls 2–6: one Open Library search per subject; results are filtered to remove NYT bestsellers, books logged by more than 500 readers, children's books and self-help, then ranked by matching subjects and rating.
  5. Output: five hidden gems, each with a "why you" reason. PostHog records the events.

Simple Architecture: [Book + reflection] → [Browser app on localhost] → [Open Library Search API] → [Five hidden gems + reasons] · [PostHog analytics]

Cost per run: $0.00. One run makes about 2–6 Open Library requests (free, no API key) and sends about 4 PostHog events (free tier: 1M events/month). Build 3 plans to add an AI model to read the full reflection; I'll measure its token cost per run before adding it.

Roadmap

  • This semester (Builds 3–5): My Bookshelf tab (save notes for many books, including favorite quotes) → Recommended for Me tab (an AI model reads all your notes and recommends books by category, with links to buy) → cloud launch.
  • Later: Explore tab (browse other readers' public bookshelves) and Book Clubs. Both need accounts, a shared database and privacy controls, so they are out of scope this semester. This changes PRD v1: affiliate links move in scope; book clubs stay out.
  • New risk: reflections can be personal (e.g. a breakup), and they will be sent to an AI model. Notes stay private by default.

Build 1 · Intent.md & Throwaway Prototype (Due Nov 9)

  • What shipped: PRD v1 and a local prototype (prototype/index.html). It finds the book you loved in Open Library, collects the reflection template, maps your three words to subjects, filters out books that are already popular, and returns five hidden gems with a reason. If Open Library can't be reached, it falls back to a small hand-picked sample shelf so the demo still works.
  • What works: The full flow runs end to end in the browser with no install and no API key.
  • Things learned with AI: The difference between Git (version history on my computer) and GitHub (where the repo lives online); creating a repo from a template; publishing docs/ with GitHub Pages; why .env is a hidden file listed in .gitignore.
  • What broke / changed in PRD: My first repo was created under my personal account and then transferred to the class organization, which removed my admin access, so I couldn't turn on Pages. I recreated the repo directly in the organization. I also moved from a map-based booking idea (too close to ClassPass) to Hidden Shelf. Matching is keyword-based for now; recommendations will get smarter when an AI model reads the full reflection in Build 2.

Build 2 · Smallest Local Version & PostHog (Due Nov 16)

  • What shipped: The app runs on localhost (python3 -m http.server) with live Open Library API calls. PostHog is installed on this Product Page and in the local app, with pageviews, clicks, session replay and four custom events. PRD v2 adds the biggest risk, how this build tests it, how the app works, and cost per run. AGENTS.md now documents the project structure and how to run it.
  • What I learned: The difference between an API call (asking another service for data) and an AI call (asking a model to reason); why the app should be served on localhost instead of opened as a file; that a PostHog project token is public by design, while private keys belong in .env.
  • What broke / changed in PRD: Testing with a real book (The Let Them Theory, described as reflective, insightful, healing) showed the limits of keyword matching: only "healing" matched a subject, so all five reasons were the same; the results mixed genres (e.g. a fantasy novel for a book about relationships); and the "moment I remember" text isn't used at all. This is the main reason to add an AI model in Build 3. I also expanded the vision into tabs (see Roadmap): affiliate links move in scope, book clubs stay out. AI was kept out of this build to keep cost at $0 and test the data source first.
  • Cost & time this week: $0.00 · 2–3 hours
